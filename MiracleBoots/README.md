# ЧудоОбувь — система оформления заказа обуви

Учебное приложение для автоматизации продажи обуви: каталог моделей, оформление заказов,
просмотр и управление заказами для менеджера и администратора, аналитика продаж с экспортом в PDF.

Приложение разработано по КИМ 09.02.07-2-2027 (инвариантная часть, задания 1–4)
и вариативной части (модуль аналитики для администратора).

## Технологии

- Платформа: .NET Framework 4.8, WPF
- Доступ к данным: Entity Framework 6 (Database First, модель `KozinModel.edmx`)
- СУБД: Microsoft SQL Server
- Экспорт отчётов: iTextSharp 5.5.13.3

## Настройка базы данных

1. Откройте скрипт `Database/KozinMiracleBoots.sql` в SQL Server Management Studio
   (или выполните через `sqlcmd`) и запустите его.
   Скрипт создаёт базу данных `KozinMiracleBoots`, таблицы, ключи, ограничения
   и загружает данные из файлов `*_import.xlsx`.

   Пример запуска через `sqlcmd`:

   ```
   sqlcmd -S .\SQLEXPRESS -E -f 65001 -i Database\KozinMiracleBoots.sql
   ```

2. Проверьте строку подключения в `App.config`:

   ```xml
   <add name="MiracleBootsEntities"
        connectionString="metadata=res://*/KozinModel.csdl|res://*/KozinModel.ssdl|res://*/KozinModel.msl;provider=System.Data.SqlClient;provider connection string=&quot;data source=.\SQLEXPRESS;initial catalog=KozinMiracleBoots;integrated security=True;MultipleActiveResultSets=True;App=EntityFramework&quot;"
        providerName="System.Data.EntityClient" />
   ```

   При необходимости замените `.\SQLEXPRESS` на имя своего экземпляра SQL Server.
   Модель ADO.NET при этом переподключать не нужно: имя базы данных и схема
   совпадают с моделью `KozinModel.edmx`.

### Схема базы данных

| Таблица         | Назначение                                      | Ключевые поля                                      |
|-----------------|-------------------------------------------------|----------------------------------------------------|
| `Roles`         | Роли пользователей                              | `ID_Role`, `RoleName`                              |
| `Users`         | Пользователи системы                            | `ID_User`, `UserLogin`, `ID_Role`                  |
| `Categories`    | Категории обуви                                 | `ID_Category`, `CategoryName`                      |
| `Subcategories` | Подкатегории (виды обуви)                       | `ID_Subcategory`, `SubcategoryName`                |
| `Manufactures`  | Производители                                   | `ID_Manufacture`, `ManufactureName`                |
| `Sizes`         | Размеры                                         | `ID_Size`, `Size`                                  |
| `Products`      | Модели обуви                                    | `ID_Product`, `ID_Category`, `ID_Subcategory`, `ID_Manufacture` |
| `StockItems`    | Товарные позиции «модель + размер» и остатки    | `ID_StockItem`, `ID_Product`, `ID_Size`, `ItemsQuantity` |
| `Orders`        | Заказы                                          | `ID_Order`, `OrderDate`, `ID_User`, `TotalAmount`  |
| `OrderProducts` | Позиции заказа                                  | `ID_OrderItem`, `ID_Order`, `ID_StockItem`, `Quantity`, `PriceAtOrderTime` |

Схема соответствует третьей нормальной форме, все внешние ключи снабжены
ограничениями ссылочной целостности.

ER-диаграмма со всеми таблицами, атрибутами, ключами и связями находится
в файле `Database/ER_Diagram.pdf`.

## Функциональность

### Каталог товаров

- Вывод моделей из базы данных: изображение, категория, наименование,
  производитель, состав, цена со скидкой.
- Количество пар: «много», если больше пяти, иначе «мало».
- Подсветка светло-красным цветом моделей, которых осталось три пары и меньше.
- Заглушка `picture.png`, если у модели нет изображения.
- Скидка 25 % на модели, по которым не было заказов в предыдущем календарном месяце.
- Поиск по наименованию и описанию, фильтрация по категории и сортировка по цене —
  в реальном времени, без кнопки «Найти».
- Поиск, фильтрация и сортировка применяются совместно.

### Оформление заказа

- Авторизация по логину из списка пользователей.
- ФИО пользователя отображается в правом верхнем углу.
- Карточка модели: изображение, производство, наименование, категория,
  цена со скидкой, состав, описание, размерный ряд и доступные размеры.
- Выбор размера и количества с контролем остатка на складе.
- Корзина, подтверждение заказа, сохранение даты заказа.
- После оформления заказа остатки на складе уменьшаются, каталог обновляется.

### Управление заказами

- Список заказов: номер, дата, ФИО клиента, сумма.
- Менеджеру доступен только просмотр списка заказов и их состава.
- Администратор может удалять заказы; товары возвращаются на склад.
- Просмотр состава заказа: модель, производитель, размер, количество,
  цена за единицу, итоговая сумма.
- Администратор может удалять товарные позиции и изменять дату заказа.
- При удалении позиции или заказа остатки на складе пересчитываются.

### Аналитика продаж (администратор)

- Период по умолчанию — текущий календарный месяц.
- Показатели: общее количество заказов за период и общая сумма продаж.
- Топ-5 моделей по количеству проданных пар: наименование, производитель, количество.
- Пересчёт показателей в реальном времени при изменении дат.
- Проверка корректности периода: дата начала не может быть позже даты окончания.
- Экспорт отчёта в PDF (период, итоговые показатели, таблица топ-5).

## Сборка и запуск

1. Восстановите пакеты NuGet:

   ```
   nuget restore MiracleBoots.sln -PackagesDirectory packages
   ```

2. Соберите решение в Visual Studio 2022 (или через MSBuild):

   ```
   msbuild MiracleBoots.sln /p:Configuration=Debug
   ```

3. Запустите `bin\Debug\MiracleBoots.exe`.

## Примечание о данных

Даты заказов из `Orders_import.xlsx` сохранены с тем же интервалом, что и в исходном
файле, но сдвинуты так, чтобы последний заказ приходился на дату загрузки данных.
Это позволяет сразу продемонстрировать расчёт скидок и аналитику за текущий месяц.
